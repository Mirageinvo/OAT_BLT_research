## Kill-shots

**1. Метод не идентифицирован.** LIBERO-LONG **[E]**: vote (CS) **0.665±0.025** ≈ medoid **0.663±0.028**. Если вклад — KDE-мода по чанку, главный сьют её не отделяет от геометрического центра. Рецензент читает best-of-N с поиском моды, не новое правило агента. «Семейство консенсуса» (grok) = {vote, medoid}, не {CS}.

**2. CS vs KDPE — одна ячейка из семи.** Единственная значимая: box-close **[E]** 68.8 vs 58.8, Δ **+10.0**, CI **[+3.6, +16.8]**, **p=0.005**; **[C]** **+6.8**, **p=0.028**. Stick jsonl **+5.6**, **p=0.12**. Coffee **[E]** **−2.8**, **p=0.25** (KDPE выше). Disassemble **[E]** **−3.2**, **p=0.38**. Формула composer «CS matches or exceeds KDPE» ложна как summary: на coffee, lift и disassemble **[E]** точечно KDPE ≥ CS. Старые stick 18.0 p=0.005 и coffee 41.6 без jsonl запрещены дампом.

**3. LIBERO без парного теста.** Разрыв vote−kdpe по средним **0.060** (0.665 vs 0.605). Std 0.025 vs 0.009. Порядок *средних* ясен. «Порядок однозначен» (grok) и «kdpe << vote» (composer) — завышение: нет CI, нет permutation. «CS значимо лучше KDPE на LIBERO» писать нельзя.

## Раскол с grok.md и composer.md

Grok честен по box-close, запрету смешивать **[E]/[C]** и по 2×. Перегиб: LIBERO как механизм («агент выигрывает, когда берёт согласованный план целиком»). Vote≈medoid ⇒ «целиком» неотличимо от medoid. Square 36.0 vs medoid 29.6 и stick-pull 28.8 vs 18.8 — точки **без** парного p; «medoid не доминирует CS» на headroom — гипотеза. «Значимого превосходства KDPE нет» верно как «нет значимой ячейки», не как доминирование CS.

Composer опаснее для reject. Вклад №2 тащит масштабирование N из Table 4 (сломанный протокол). «kdpe << vote» без p. Headroom на square/stick при p=0.32 и 0.12. Вести статью диагностикой K/R (PDF 1–3) имеет смысл только если комитет *принимает* старые таблицы; иначе это маскировка слабого нового эмпирика. «Selection — да» как общий принцип опровергается RM-потолком и RC-неразделимостью. Сводить vote≈medoid к «KDE mode-seeking» — контрабанда KDE в ничью.

Оба недооценивают множественные сравнения. Честный объект — **ранжирование правил выбора на одном сьюте**, плюс один значимый MW-кейс.

## Что выживает (узкий AAMAS)

Не method-win. Диагностика + ранжирование, явно scoped.

**Защищаемый тезис.** У замороженной action-chunking политики на LIBERO-LONG (OAT8, `n_test=500`, 5 эксп., **[E]**) правило выбора среди N=8 кандидатов меняет suite-SR по *порядку средних*: consensus по чанку (vote **0.665±0.025**, medoid **0.663±0.028**) выше endpoint-KDE (**0.605±0.009**), max_ll (**0.584±0.010**), base (**0.558±0.018**) и random (**0.554±0.015**). Random≈base: сам N не помогает. Likelihood не объясняет зазор до consensus. Endpoint-ядро до consensus на этом сьюте не дотягивает. Это ранжирование протокола, не causal identification KDE и не доказанная значимость.

**Вне LIBERO — негатив в теле.** CS vs KDPE: значим только box-close; **[C]** подтверждает знак/порядок, в средние не идёт. Остальное n.s. Текущий RoboMimic — насыщение (base≈CS). RoboCasa — неразделимость, KDPE неприменим. Перенос ранжирования не показан.

**K/R (PDF Tables 1–3).** Фон, если старые таблицы остаются. Не «мы опровергли AAC/PACE», а: на LIBERO/OAT с random-контролем адаптивный K/R не бьёт matched-cost. Новых чисел в дампе нет — не обновлять.

**Латентность.** Selector-only CS ~2× KDPE на D=7; e2e оба ~28 мс. Не Pareto времени реакции. Канон Table 5 = can GPU1; LIBERO 0.272 / 0.553 — подтверждение D=7, не замена.

**Крюк без костюма.** На каждом replan агент обязан выбрать один чанк. Куда девать test-time compute: не в адаптацию K/R (старая диагностика); среди дешёвых селекторов на длинном сьюте consensus по траектории ранжируется выше likelihood и конечной точки. Это не уникальность CS и не multi-suite law.

**Протокол.** Paper scalars = **[E]**, ± = std по 5 повторам, сноска SE=std/√5. RM/MW: 5×50 сцен (`test_start_seed=10000`), позадачные ckpt. LIBERO: 500 rollouts, 5 эксп. **[C]** — приложение, без пула. Table 4 PDF — historical, mixed ±, RM base = другой пайплайн (n250). Наши random/medoid не сравнивать с PDF CS-8.
