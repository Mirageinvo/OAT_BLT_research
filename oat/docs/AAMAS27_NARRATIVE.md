## Что числа говорят

**1. На LIBERO-LONG selection работает, и это не «ещё N сэмплов».**

Suite SR (`mean_success_rate_mean`, n_test=500, 5 эксп.):

| | vote (CS) | medoid | KDPE | max_ll | base | random |
|--|-----------|--------|------|--------|------|--------|
| SR | **0.665** | 0.663 | 0.605 | 0.584 | 0.558 | 0.554 |
| vs base | **+10.7 pp** | +10.5 | +4.7 | +2.6 | — | −0.4 |

Это главный новый факт поверх PDF. PDF уже показывал, что CS поднимает SR относительно base и что adaptive K/R при том же среднем бюджете не бьёт random. Overlay отвечает на *почему CS*: тем же N=8.

- **random ≈ base** (0.554 vs 0.558). Взять любой из N чанков бесполезно. Выигрыш — правило выбора, не размер пула.
- **max_ll ≈ base+2.6 pp** (0.584). Самый вероятный токен-путь политики почти не лучше одиночного сэмпла. CS — не «более уверенный AR».
- **KDPE base+4.7, CS base+10.7.** Геометрия *конечной точки* чанка (индекс R−1) забирает часть эффекта и **не весь**. На длинном сьюте консенсус по *всему* нормализованному чанку сильнее endpoint-KDE на ~6 pp.
- **vote ≈ medoid** (0.665 vs 0.663). Это не провал CS. Это идентификация: выигрыш живёт в **моде облака чанков**, не в конкретной формуле KDE. CS (vote) — метод статьи; medoid — абляция, которая показывает тот же механизм дешевле на шаге селектора. На задачах с запасом medoid *не* заменяет CS (square 29.6 vs 36.0; stick-pull 18.8 vs 28.8).

Где CS забирает suite: K6, LR1, LR2a, LR5 — длинные многошаговые задачи, не потолок. Это тот же compounding, что в PDF: маленькое качество чанка × десятки replan.

**2. CS на Table 4 воспроизводится. Сломан PDF-base RoboMimic, не CS.**

Наш vote vs PDF CS-8 (одинаковый протокол N=8, seed 10000): can **85.6 = 85.6**, square 32.0 vs 31.0, stick-pull 26.8 vs 25.6, box-close 69.6 vs 67.2, close-drawer 56.8 vs 56.4. Метод на месте.

Наш **base** на can/lift выше PDF (can 84–88 vs 76.3; lift 96 vs 90.5) на тех же сценах и ckpt. Парный can CS−base +1.2, p=0.78: в *текущем* eval запас на can закрыт, потому что base уехал вверх, а не потому что CS перестал работать. PDF can +9 pp — другой замер base (n250). В статье: Table 4 оставляем с явным протоколом; новые селекторы сравниваем **внутри нашего пайплайна**; saturation на can/lift — ожидаемый потолок, не контрпример.

**3. KDPE — честный внешний baseline, не соломенный. CS его не «уничтожает на всех задачах» и не обязан.**

Парные [E]: значимый CS>KDPE только **box-close** (+10.0, p=0.005; [C] +6.8, p=0.028). Остальное n.s. (stick +5.6 p=0.12; coffee −2.8; disassemble −3.2; RM ничья). Значимого KDPE>CS нет.

Читать так, а не «одна ячейка = нет результата»:

- На **LIBERO** (десятки задач×инитов) KDPE стабильно ниже CS (~6 pp, маленькая std у KDPE 0.009).
- На **потолочных** RM селекторы неразличимы — так и должно быть.
- На **MW** геометрия конца иногда близка к консенсусу (coffee, disassemble); там, где важен весь чанк, CS впереди (box-close значимо, stick по знаку).
- Offline: KDPE≠vote 75–78% индексов — это другой селектор, не переименованный vote.

Формулировка: *CS matches or beats KDPE; the only paired-significant win is box-close; the suite-level separation is LIBERO.* Не: «CS лучше KDPE на MetaWorld».

**4. RoboCasa — не витрина overlay.** Селекторы на aic4 лежат друг на друге; наш CS на 3–8 pp ниже PDF CS-8 (microwave 46.4 vs 54.8). KDPE n/a (12D). Одна строка: kitchen 12D, селекторы не разделяются, ccm discarded. Не строить вокруг RC ни тезис, ни «CS не работает».

**5. Латентность.** Сравнивать селекторы нужно на **selector-only**: генерация общая (один CNN, N AR). Канон Table 5, H100, can, N=8: CS **0.264** мс, KDPE **0.535** (~2×), medoid 0.101, max_ll 0.023, random 0.010. IQR CS vs KDPE не пересекаются. KDPE с 16→32 почти не растёт (launch-bound, ~72 kernel’а). LIBERO D=7 совпадает с can (0.272 / 0.553).

Полный forward ~28 мс у обоих, Δ ~0.3 мс. Это **не** опровержение Table 5: 2× — про стоимость *правила выбора* при общей генерации. В тексте одно предложение: we do not claim end-to-end 2×. D=4 KDPE дешевле CS (~0.20 vs 0.27) — не пул с D=7.

## Нарратив для AAMAS (как писать)

**Тезис PDF (оставить).** Prefix-decodable chunks обещают anytime fidelity, но крутить K и R по эвристикам не бьёт фиксированный бюджет (Tables 1–3). Лишний test-time compute лучше тратить на выбор среди кандидатов после одного прохода восприятия.

**Что overlay добавляет (вклад).** Не «ещё один BoN». **Какое правило выбора.** На LIBERO-LONG:

1. пул без правила ≈ одиночный сэмпл (random);
2. правило «верю политике» почти бесполезно (max_ll);
3. правило «верю конечной позе» частично (KDPE);
4. правило «верю моде всего чанка» забирает ~11 pp (CS / medoid).

AAMAS-угол: на каждом replan агент **обязуется** к одному из N планов. Вопрос — aggregation rule, не новое обучение. CS — рабочая реализация (KDE-vote); medoid показывает, что семейство — consensus/mode, не likelihood.

**Структура.** (1) K/R negative из PDF. (2) CS + scaling из Table 4, vote сверен. (3) **Новая** таблица LIBERO: 6 селекторов. (4) RM/MW: CS vs KDPE, box-close, потолок can/lift. (5) Table 5 selector-only + e2e оговорка. (6) Limitations: RM base drift; RC; [E] vs [C]; ± = std.

**Abstract не должен.** «CS 2× faster inference». «CS significantly beats KDPE on MetaWorld». PDF can +9 pp как результат *этого* eval. Workshop-оговорки.
